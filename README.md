# Research Radar — AI & Quant Intelligence

A source-first, static research feed for AI researcher blogs, AI engineering practice, academic research, quantitative trading firms, and interviews/podcasts.

**First-version principles**

- No AI API, LLM summaries, embeddings, or paid service dependencies.
- Article cards show the original title, source, publication date when available, topics, and direct publisher link.
- The initial source directory is seeded from [AI博客资源-完整索引](https://github.com/joeseesun/ai-blog-res/blob/main/AI%E5%8D%9A%E5%AE%A2%E8%B5%84%E6%BA%90-%E5%AE%8C%E6%95%B4%E7%B4%A2%E5%BC%95.md), then extended with quantitative firms and interview/podcast sources.
- GitHub Actions checks sources daily and commits updated JSON files. GitHub Pages hosts the static site.
- Some sources do not expose a stable RSS/Atom feed or a clear public archive. They remain visible in the source directory; collection coverage is reported honestly in `data/collector_status.json`.

## Create the GitHub repository

1. On GitHub, create a **new public repository** named `ai-research-radar`. Do not initialize it with a README, license, or `.gitignore` because these files are already included here.
2. Download and unzip this project, then open a terminal in the `ai-research-radar` folder.
3. Run the commands below, replacing `YOUR_GITHUB_USERNAME` with your account name:

```bash
git init
git branch -M main
git add .
git commit -m "Initial Research Radar site"
git remote add origin https://github.com/YOUR_GITHUB_USERNAME/ai-research-radar.git
git push -u origin main
```

If Git asks you to authenticate, use your normal GitHub sign-in flow or Git Credential Manager. Do not paste a personal access token into this repository or into chat.

## Enable GitHub Pages

1. Open the repository's **Settings → Pages**.
2. Under **Build and deployment → Source**, choose **GitHub Actions**.
3. Open **Actions** and allow workflows to run if GitHub asks.
4. The `Deploy Research Radar to GitHub Pages` workflow should run after the first push. When it succeeds, the site URL will be shown in the workflow's deployment environment and usually follows this form:

   `https://YOUR_GITHUB_USERNAME.github.io/ai-research-radar/`

The exact URL cannot be confirmed until the repository exists and Pages deployment succeeds.

## Run the daily collector

The `Update article index` workflow runs daily at **00:17 UTC (08:17 Singapore time)**. It first parses the upstream AI blog Markdown index for newly listed sources, then checks the registered sources for posts. GitHub can delay scheduled jobs during periods of high load. You can also run it manually:

1. Open **Actions → Update article index**.
2. Click **Run workflow**.

The workflow uses the repository's built-in `GITHUB_TOKEN` with `contents: write` to update `data/sources.json`, `data/articles.json`, and `data/collector_status.json`. No custom secret or API key is required. When the collection workflow finishes, the Pages workflow redeploys the latest repository state (including the refreshed JSON files).

## Add or edit sources

Edit `data/sources.json`. A source has this shape:

```json
{
  "id": "example-lab",
  "name": "Example Lab Blog",
  "url": "https://example.com/blog",
  "category": "ai-company",
  "source_type": "official-blog",
  "topics": ["agents", "evaluation"],
  "language": "en",
  "description": "Official research and engineering posts.",
  "tier": null,
  "enabled": true,
  "feed_url": "https://example.com/blog/rss.xml",
  "source_index": "manual"
}
```

Allowed categories currently used by the interface:

- `ai-researcher` — individual researchers and personal blogs
- `ai-engineering` — prompt/context engineering, coding agents, skills, workflows, and practical AI engineering
- `ai-company` — AI labs and company blogs
- `ai-academic` — universities and research institutes
- `quant-firm` — quantitative trading firms and systematic investment managers
- `interviews` — interviews, talks, and podcasts
- `ai-community` — research communities and discussion forums

For quant firms, set `tier` to `Tier 1` through `Tier 5`. Tiers are a **monitoring-priority convention**, not an objective ranking of firm quality or performance.

If a site has a known feed URL, set `feed_url`. The collector checks `robots.txt` when reachable, tries RSS/Atom autodiscovery first, then common feed paths, then a sitemap, and finally a small number of links from the source page. For sites that disallow crawling, block automated requests, or lack a usable public archive, collection may not work; adjust or disable those sources rather than repeatedly hitting them.

After editing source records, the next scheduled or manually triggered run will use them. `scripts/seed_sources.py` is only for rebuilding the initial seed list; running it again overwrites `data/sources.json` with the seed directory.

## Local development and checks

The website is static; serve the repository root using any local static server. For example:

```bash
python -m http.server 8000
```

Then open `http://localhost:8000`.

To sync the upstream source directory and run the collector locally:

```bash
python -m pip install -r requirements.txt
python scripts/sync_source_index.py
python scripts/update_content.py
```

For a limited, non-writing test run, use `python scripts/update_content.py --limit 8 --dry-run`.

## Important collection behavior

- The collector does not generate summaries or infer publication dates with an LLM.
- If a publication date is not available from the feed/page, the site shows the discovery date and marks the publication date as unknown.
- RSS/Atom entries are preferred. Sitemap `lastmod` is only a fallback hint and may represent page modification rather than original publication.
- The collector stores title, original URL, source metadata, publication/discovery dates, topics, and publisher-provided excerpts when present. The UI intentionally does not display excerpts in this first version.
- URLs are deduplicated after removing common tracking parameters. Article records older than 365 days are pruned on collection.
- This is an index of links and metadata, not a mirror of article content. Respect each publisher's robots policy and terms.

## Known first-version limitations

- Source coverage is best-effort; a tracked source is not a guarantee that every new post will be discovered.
- Some quant firms primarily publish through interviews, conferences, or third-party podcasts rather than a public blog. Those sources may need additional direct episode feeds or manually added archive URLs.
- The current site has no database, login, saved articles synced across devices, email newsletter, AI summaries, or personalized ranking.
